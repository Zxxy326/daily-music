## Daily Music（原 Love listening to music）方案定型

**背景**：用户要参考 md3Music（Flutter+Rust，AGPL-3.0）做一款在线听歌软件，用 MiuiX 组件构建。走 grill-me 流程，共 5 轮 20 个问题。

**关键转折**：用户指定的是官方 `compose-miuix-ui/miuix`（Kotlin/Compose，Apache-2.0），不是 Flutter 移植版 `flutter_miuix`。这直接推翻了「fork Flutter 项目换 UI」的原始设想。

**实测数据（供后续引用）**：
- 上游 `lib/`：517 文件 / 216,060 行；260 文件（69% 代码）绑死 Material 家族
- 上游用独立包 `material_ui: 1.7.0` + `m3e_core`，不是 Flutter 内置 material
- 实际只用到 85 个 Material 符号，前 20 个占 89% 调用，其中 65% 是 Icons/Colors/Theme 常量访问
- 播放页双实现：`full_player.dart` 254 KB + `full_player_am.dart` 277 KB
- Rust 服务：`kugou_api_server/rust`，17,875 行 / 50 模块，cdylib+rlib，含 jni 导出

**最终决策**：
- 技术栈：纯 Android 工程 + Jetpack Compose + 官方 Miuix（不做 KMP 骨架）
- 播放：Media3 ExoPlayer；USB 独占只留 AudioSink 接口
- 复用：只拿 Rust 服务；接入方式用 JNA 调 4 个与类名无关的 C 符号（`start_server` / `stop_server` / `is_server_running` / `get_server_port`），绕开上游写死的 `Java_com_md3music_premium_...` JNI 符号
- 范围：核心七件套 + 扫码登录；TV 不做
- 命名：`com.dailymusic.app` / 显示名 Daily Music
- 发布：仅自用不公开（规避 AGPL 与酷狗 API 风险）

**产出**：`PLAN.md`（决策记录 + 架构 + M0-M5 里程碑 + 风险 + 验收）

**环境事实**：JDK 17 Corretto、Android SDK 36/35、NDK 27.0（上游要 28.2）、Rust 1.98、AVD `vp_phone`/`tvdesk_tv`（仅 API 30 image）、**无真机**、**未装 Flutter**（KMP 路线下不需要）。上游已浅克隆到 `.tmp/upstream/`（约 300 MB，未纳版本管理，用户未要求删除）。

**未定事项**：Miuix 依赖方式（Maven 锁版本 vs vendor）、登录方式、歌词移植深度、收藏/历史是否复用上游 schema。

## 追加：四项待定已定 + 三屏视觉稿

**用户决定**：① Miuix 走 Maven Central 锁版本 ② 登录三种都做（扫码/手机号/Cookie） ③ 歌词逐字+翻译+罗马音一起移植 ④ 收藏历史复用上游 schema。另加需求：**悬浮液态玻璃底栏**（iOS 风格）。

**新发现的技术硬约束**：`miuix-blur/build.gradle.kts` 里 `minSdk = 33` → 玻璃效果把 App 的 minSdk 顶到 Android 13。而现有 AVD `vp_phone` 是 android-30 image，**跑不了模糊**，需装 API 33+ image 或真机验证。

**上游数据层实况**：`lib/` 里只有 `listen_stats_db.dart` 一处 `CREATE TABLE`（表 `play_records`）；收藏不在 SQLite，而在 `favorites_repository` / `local_favorites_repository`（shared_preferences 系）。所以「复用上游 schema」实际是复用两套存储结构，不只是建表语句。

**产出**：`design/mockup.html` 三屏高保真稿（首页/播放/歌词，含明暗切换，`?dark=1` 可强制深色），静态预览 `design/final-light.png`、`design/final-dark.png`。

**渲染踩坑记录**：用 Edge headless 截图验证（`msedge.exe --headless=new --screenshot=...`），踩了三个坑：
1. `<button>` 未重置 `background` 会被 UA 默认按钮底色染白 —— `.ctl` 漏写，深色下变白圆
2. 玻璃底栏一开始加了下缘渐隐遮罩，导致背后没内容可透，看不出玻璃感 —— 删掉遮罩让列表穿过玻璃
3. 内容实际比预估低约 200px，按估算摆位会把元素排到屏幕外 —— 必须用 `transform:scale` 放大版核对真实位置

## M1 地基完成（工程已跑通）

**产出**：可编译可运行的 Android 工程，APK 35MB（双 ABI），模拟器 `daily_phone`（API 35）实测通过。

**版本矩阵（实测，别再试错）**：
- Gradle 8.14.3 / AGP 8.11.0 / Kotlin 2.4.21 / compileSdk **37** / targetSdk 35 / minSdk 33
- Miuix **0.9.3** / JNA 5.19.1(aar) / JDK 17 Corretto / NDK 27.0

**踩过的版本坑**：
1. **Miuix 全部版本（0.9.0–0.9.4）的 aar-metadata 都要求 minCompileSdk=37** —— 没有「降版本换低 compileSdk」的路，必须装 `platforms;android-37.0`（目录名带 `.0`，Android 17 起有次版本号）。
2. 0.9.4 还要 AGP ≥9.1（拉 Compose runtime 1.12）；0.9.3 拉 Compose 1.11.1（minAGP 8.6），所以锁 0.9.3 才能在 AGP 8.11 上跑。
3. AGP 8.11 最高推荐 compileSdk 是 36，用 37 需在 gradle.properties 加 `android.suppressUnsupportedCompileSdk=37`。
4. `FloatingNavigationBar` / `FloatingNavigationBarItem` 在 0.9.0 就有；示例里还有 `IosLiquidGlassNavigationBar`（example/component/liquid/），是液态玻璃底栏的直接参考实现。

**重大环境坑（务必记住）**：Rust 交叉编译在**受限沙箱里会永久卡死** —— `clang.exe` CPU 时间恒为 0、无子进程，卡 40 分钟零产物。`dangerouslyDisableSandbox: true` 重跑后 **32 秒**编完。以后编 Rust 一律要放开权限。

**JNA 接入方案（已验证可用）**：不改 Rust 一行，用 JNA 调 `start_server(port, dataDir)` / `stop_server()` / `is_server_running()` / `get_server_port()` 四个 C 符号，绕开上游写死的 `Java_com_md3music_premium_...` JNI 包名。`Native.load("kugou_server", ...)` 直接读 APK 里的 libkugou_server.so。

**实测证据**：服务起在 127.0.0.1:17150；`adb forward` 后 `curl /login/qr/key` 返回真实酷狗登录二维码（base64 PNG）—— 说明 Rust 服务真的调通了酷狗接口，不只是「端口能连」。
